# Phase 7 — Streamlit UI

**Status:** ✅ Done (2026-10-27): tested headless (`AppTest`) and driven in a real browser against the user's syllabus with Gemini · Code: `app.py` (layout), `citerag/ui.py` (helpers), `.streamlit/config.toml` · Tests: `tests/test_ui.py` (23), 197 passing in total · Updated 2026-11-10: formulas are rendered (Step 7)

## Goal

A web page where the user adds documents, asks questions, and can check every answer: each citation opens to the exact passage and the PDF page it came from, and statements the sources don't support are highlighted.

## Step 1 — What the page does

**Sidebar: documents**
- Lists the indexed files with chunk counts. ✕ removes a file from the index; the file itself stays in `data/`, so nothing the user owns is deleted.
- **Add documents** (PDF/TXT/MD): files are saved into `data/` and indexed straight away. A file with the same name replaces the old version, and the Phase 3 fingerprints re-embed it only if its text changed. A scanned PDF with no text gets a plain error.
- **Rescan data/ folder**: indexes new or changed files and drops files that are gone, so the index mirrors the folder, the same as `python -m citerag.store data/ --prune`.

**Sidebar: settings**
- Answer with Gemini (free tier) or Claude, defaulting to `CITERAG_LLM_PROVIDER`. A warning appears if that provider's key isn't set, and Gemini shows the free-tier privacy note.
- Search in (limit to some documents), passages given to the model (k, 1–10), check citations (on), strict mode (off), clear chat.

**Main area:** question at the bottom (`st.chat_input`). Each answer shows:
1. The answer, streamed as it's written. Citation markers become superscripts. A statement that failed the Phase 6 checks gets a yellow background, with its reasons as a tooltip.
2. One gray line: "4/5 statements supported by their citations, 1 warning. Unsupported statements are highlighted."
3. One expander per citation, `[1] syllabus.pdf, p. 3`. It holds the section and the **whole passage with the quote highlighted**, plus a **Show PDF p. 3** toggle that renders just the cited page(s): pypdf cuts them out of the file, and `st.pdf` displays them.
4. **Checks**: every statement with ✓ or ✗, its reasons and its support score. Statements removed by strict mode are struck through.
5. **Retrieved passages**: all k passages the model was given, cited or not, with their dense, keyword and RRF scores. This is for seeing why an answer came out as it did.

Strict mode doesn't stream (removed text can't be taken back), so the answer appears once it has been checked.

## Step 2 — Design: plain on purpose

The user asked for a simple page that doesn't look AI-generated. So:
- no emojis in the title or headings, and no chat avatars: each turn is the question in bold, then the answer
- short wording
- Streamlit's default theme, no custom CSS file
- the only colour is the yellow highlight, used for quotes and for unsupported statements
- the toolbar is minimal (no "Deploy" button or developer menu)
- the check marks are plain ✓ and ✗

## Step 3 — Safety

| Risk | Defence |
|---|---|
| A document contains instructions ("output this HTML") and the LLM copies them into its answer; rendering with `unsafe_allow_html` would run it | All LLM and document text is HTML-escaped before our own `<span>`/`<mark>`/`<sup>` tags are added. Tested with an `<img onerror=…>` answer |
| Markdown images in an answer (`![](https://…?data)`) would be fetched as soon as the answer shows, which could leak data | Images are removed; only the alt text stays |
| `$…$` in an answer is rendered as LaTeX | Until 2026-11-10 every `$` was escaped. Now formulas are rendered and any other `$` is escaped (Step 7). Inside a formula `<`/`>` become `\lt`/`\gt`, so it can't carry an HTML tag, and Streamlit's KaTeX runs without `trust`, so `\href`/`\url` do nothing |
| An upload named `../../x.pdf` writes outside `data/` | Only the bare file name is kept; hidden files and other extensions are rejected |
| A cited source path pointing outside `data/` when showing a PDF page | `source_pdf` resolves the path and refuses anything outside `data/` |
| **The app was reachable from the whole network**: Streamlit listens on every interface by default (its log showed a "Network URL" and an "External URL") | `.streamlit/config.toml`: `server.address = "localhost"`. Verified: it listens on `127.0.0.1:8501` only |
| Streamlit sends usage statistics by default | `browser.gatherUsageStats = false`, as with ChromaDB's telemetry in Phase 3 |

## Step 4 — Wiring

- **Models load once per server** (`st.cache_resource`): the store and embedding model, the retriever, the NLI validator, and one backend per provider. Both models load before the first question, behind a "first run only" spinner.
- A `Generator` is created per question from those cached parts, with that question's settings (validate/strict).
- **Streaming:** the `on_text` callback rewrites one placeholder as pieces arrive, followed by a "▌" cursor. The finished answer then replaces it in its checked form.
- **Text positions:** `validator.display_offsets` maps a statement's position in the plain answer text to its position in the displayed text, which has `[n]` markers in it. The UI uses it for highlighting, and strict mode now uses it to cut text, so the two can't disagree about where a statement is.
- Cited PDF pages are cached (`st.cache_data`) by path, modification time and page range.

**Dependency:** `streamlit[pdf]` adds `streamlit-pdf` 2.1.0, the official viewer component (released 2026-09-28; the dependency check is clean). `requirements.txt`: `streamlit[pdf]>=1.66`.

## Step 5 — Problems found by running it

1. **Model descriptions printed on the page.** The preload lines (`store.embedder.model`) were bare expressions, and Streamlit "magic" draws any bare expression in the main script. They're now an assignment, and a regression test fails if the preload draws anything (checked by putting the bug back).
2. **840 lines of `No module named 'torchvision'` tracebacks in the server log.** On every rerun, Streamlit's auto-reload watcher inspects every loaded module. Touching transformers' lazily loaded image modules makes them try to import torchvision, which isn't installed or needed. → `server.fileWatcherType = "none"`. Streamlit restarts the watcher when a browser session reconnects, ignoring that setting (seen after an upload), so `app.py` also quietens that one logger. Trade-off: the app no longer reloads by itself when code changes; restart it.
3. Small fixes: "1 chunks" became "1 chunk", and "(Phase 6)" was removed from the help text.

## Step 7 — Formulas (2026-11-10)

**Problem.** Asked for the Scaled Dot-Product Attention formula from "Attention Is All You Need", the answer was right but showed as raw source: `$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$`, and `$Q$`, `$d_k$` were shown with their dollar signs. Step 3 escaped every `$` so that "$5 and $10" wouldn't become math, which also stopped real formulas from rendering. The PDF text gives the formula as `Attention(Q,K,V ) = softmax(QKT√dk)V (1)`. The model rebuilt it correctly in LaTeX, so retrieval and generation were fine; only the display was wrong.

**Fix (`citerag/ui.py`).** Formulas are found and passed through as markdown math. Everything else is escaped as before.
- `$$…$$` is display math. It may span lines, but not a blank line.
- `$…$` stays on one line and follows pandoc's rules: no space just inside the dollars, and no digit right after the closing one. So "$5 and $10", "$5-$10" and "$5, or $50" stay text.
- A `\$` the LLM escaped itself stays a dollar sign. Before, it became `\\$`, which un-escaped it.
- Streamlit draws `$$…$$` in running text at inline size. It shows a display block only for a fence on its own lines (read from its bundled `rehype-katex`: display mode needs the `math-display` class, which only block math gets). So a `$$…$$` on its own line becomes a `$$` block, kept at the line's indent so it stays inside a list item. Elsewhere it becomes `$\displaystyle …$`.
- A highlighted (unsupported) statement never ends inside a formula; the highlight grows to cover it. `[n]` inside a formula is not turned into a superscript.
- Streaming uses the same code, so a formula shows as source until its closing `$` arrives, then renders.
- The Checks list needed no change: statements there already have LaTeX turned into plain text (`plain_math`, Phase 8).

**Safety.** Math is like a code span: markdown and HTML aren't parsed inside it. In case Streamlit ever splits the text differently from us, `<` and `>` in a formula become `\lt` and `\gt`, so no formula holds a `<` that could start a tag. Streamlit's KaTeX runs with `trust` off, so `\href`, `\url` and `\html…` render as plain red text.

**Checked in a real browser** (headless Chrome via Playwright from a throwaway `uv` env, a scratch page rendering `answer_markdown` output):
- the attention answer shows one display formula, inline Q, K, V and d_k, and its list
- prices stay text
- `$$…$$` mid-sentence and in a list item render
- `$a <img onerror=…> b$` and `\href{javascript:…}` produce no `img`, no `javascript:` link and no script run
- a highlight around a formula keeps the formula inside it
- a half-streamed formula stays as source
- no console errors

## How to run

```bash
streamlit run app.py     # http://localhost:8501
```

## Known limitations

- **Single-turn:** each question is answered on its own; follow-up questions don't see earlier answers. *(Fixed in Phase 12: follow-ups are rewritten into standalone questions; see [12-conversations.md](12-conversations.md).)*
- The chat history lives in the browser session and is lost on reload. *(Fixed in Phase 12: chats are saved and reopen from the address.)*
- No auto-reload on code changes (Step 5).
- A citation's PDF page range is the chunk's (Phase 5 limitation), so "Show PDF" can show two pages when the quote is on one.
- Formula detection is a heuristic. `$HOME/$USER` would render as math, and `\(…\)` / `\[…\]` delimiters aren't rendered; both LLMs write `$` for math.
- Checking a passage at the source depends on the PDF text as extracted. See the Phase 6 note on misleading text order.
